# Android UI review — 2026-10-03

## Scope

Coordinated UI improvements for conversations, chat, creation, Claude session history and settings. The warm olive palette and existing product flows are retained.

- Shared page headings, empty/loading/error/connection states and typography.
- Conversation cards with readable two-line titles and actionable search empty states.
- Fixed composer controls below scrollable input and attachments.
- Navigation hidden while the IME is visible, restored directly from current insets; search IME action dismisses the keyboard.
- Adaptive creation grid with font-scale-aware cell widths and full-span status rows.
- Creation composer minimum budget increased from 96dp to 160dp after checking the fixed action row and padding budget.
- Compact, dark, large-type and short-viewport Compose Preview fixtures.

No authentication protocol, ViewModel mutation rules, server API, release signing requirements or production network security settings were changed.

## Retained prerequisite fixes

The test-only MockWebServer origin is pinned to IPv4, following the existing `85cee7a` branch fix. The previously failing disconnect/redirect case encountered the alternate localhost address with connection retries disabled; the test now stays on one address without weakening production retry or redirect policy.

Both Credential Manager artifacts are fixed at `1.6.0`, and `src/passkey/java` is selected unconditionally. Native passkey inclusion no longer depends on a pre-existing Gradle cache. Hardware passkey sign-in has **not** been tested.

## Emulator status and limits

Official Google SDK packages installed in the existing execution environment:

- Android Emulator `37.2.12.0` (build `16428233`).
- `system-images;android-36;default;x86_64`, revision 2.
- Dedicated AVD `agent_ui_api36`.

Disk and memory are sufficient (about 25 GiB free disk after installation, approximately 18 GiB total RAM). Hardware acceleration check exits 3 with `KVM requires a CPU that supports vmx or svm`; `/dev/kvm` is absent and the CPU flags expose neither vmx nor svm.

Software emulation was actually attempted using:

```sh
emulator -avd agent_ui_api36 -accel off -gpu swiftshader \
  -no-window -no-audio -no-snapshot -memory 2048 -cores 2 -no-boot-anim
```

The guest became adb-accessible and started Package Manager, Window Manager and Activity Manager. APK installation first failed with `Can't find service: package`, then `Error: device is still booting.` `sys.boot_completed` remained empty. At 14:22:23 UTC, the Android watchdog logged `WATCHDOG KILLING SYSTEM PROCESS: Blocked in handler on main thread (main) for 72s`, followed by SystemUI `DeadSystemException` and system-server restart. This happened before the APK could be installed. A framebuffer capture was entirely black; it is a system-startup diagnostic, not an application screenshot.

No Android watchdog, authentication or security checks were disabled. The emulator also reported that its console authentication token could not be written outside the workspace; adb itself became available. There is no evidence that this warning caused the system-server failure. No working application UI session has been obtained, so navigation/chat/creation/keyboard, narrow-screen and large-font interaction checks remain unverified in this environment.

The repository has Compose Preview declarations but no screenshot test runner, Paparazzi, Roborazzi, or Robolectric setup. Preview sources compile; they have not been rendered in this environment.
